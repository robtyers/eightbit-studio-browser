Z80 processor and system boundaries

A processor executes instructions that move and transform bytes. A BASIC statement can require many such instructions. Assembly gives you direct control of registers and memory, but you must arrange storage, bounds, return addresses and any machine state your routine changes. Start with a short routine that returns; inspect it one instruction at a time before adding hardware access.

Bytes, words and addresses

An eight-bit byte holds 0–255. The same bit pattern can represent a signed value from -128 to 127, a character, a colour or eight on/off switches. The instruction and your programme decide its meaning. A 16-bit word holds 0–65535. The Z80 addresses 65536 byte positions; extra physical RAM needs machine-specific bank switching. A 128K Spectrum does not acquire 17-bit Z80 addresses.

SjASMPlus accepts decimal and hexadecimal operands such as 64 and $40. BASIC examples use decimal unless BIN is explicitly shown. A word stored in memory uses the low byte first: $1234 occupies $34 followed by $12. This is little-endian order. An address in HL is a value until an instruction dereferences it: LD A,L copies a register; LD A,(HL) reads the byte at the address in HL.

Flags are results with a short lifetime

S marks the top bit of an eight-bit result, Z marks a zero result and C usually records a carry or borrow. P/V means parity for logical operations and signed overflow for many arithmetic operations. H records a carry between the low and high nibbles; N distinguishes addition from subtraction for decimal adjustment. Bits 3 and 5 have undocumented behaviour and are outside this guide’s programming contract.

Flags are not a persistent comparison object. CP 10 sets flags as if A minus ten had been calculated, leaving A intact. Follow it with the branch that consumes those flags. Inserting an arithmetic instruction between CP and JP Z changes the question being tested. LD normally preserves flags, but LD A,I and LD A,R are exceptions. Consult the instruction entry before depending on preservation.

Calls and the stack

CALL places the address of the next instruction on the stack and transfers control. RET removes that address and resumes the caller. PUSH HL saves a pair; POP HL restores it. Restore pairs in reverse order. A single unmatched PUSH causes RET to interpret saved data as an address. Stack damage often looks like a crash far away from the original mistake.

Write a routine contract beside its entry: inputs, outputs, changed registers and changed flags. Saving all registers is easy to explain but costs time and stack space; saving only those promised to the caller makes a routine clearer. If your output is in A, do not restore an old AF over that output. A Spectrum loader calls your entry from BASIC in Run; Debug starts a separate snapshot and does not provide the same ROM workspace.

Instructions are shared; hardware is not

LD, ADD and CALL have processor meanings on both Spectrum and ZX81. A screen address, keyboard port, ROM entry or tape loader belongs to the selected machine. Read the Spectrum memory and ROM articles before using those addresses. Do not copy Spectrum screen or sound examples into ZX81 projects. Undocumented instructions, Z80N extensions and banked applications are not supported by this source workflow.

Learning order: read Addressing modes, then Arithmetic and comparisons, then Loops, tables and routines. Use the Instruction reference while writing code. The complete Spectrum assembly project supplies a bounded first programme and a debugger checklist; the examples in these processor articles use the Spectrum ORG 24576 harness where marked as complete listings.

Z80 addressing modes

An operand tells an instruction where its value comes from or goes to. Similar-looking expressions can mean very different operations. Before writing a loop, state whether each operand is a value, an address or the contents of that address. Parentheses usually denote a memory or port access in Z80 syntax; they are not decoration.

Not every combination is an instruction

LD (HL),(DE) is not a general memory-to-memory copy. Read through one pointer into A, then write A through the other pointer, or use a block instruction with its specified registers. Similarly, ADD HL,DE exists, while an arbitrary ADD BC,DE does not. The instruction reference describes families of valid forms; SjASMPlus diagnoses exact operand combinations. Studio’s preliminary allow-list is not an operand-level assembler.

Eight-bit immediate values must fit a byte. Loading 300 into A cannot store the number you intended. A label used as a byte operand may be an address much larger than 255. Use a word directive or a 16-bit pair for addresses. For indexed data, the offset is part of the instruction encoding; it is not a second register added at runtime.

Watch a pointer copy

    ORG 24576
    PUSH HL
    PUSH DE
    PUSH BC
    LD HL,source
    LD DE,destination
    LD BC,4
    LDIR
    POP BC
    POP DE
    POP HL
    RET
source:
    DB 3,6,9,12
destination:
    DS 4,0

Expected result: the four destination bytes become 3, 6, 9 and 12. The routine then returns. Source bytes are unchanged. LDIR increments HL and DE and decrements BC for every byte, so saving those pairs preserves the caller’s values. In the debugger, stop before and after LDIR and inspect destination. A single Step may cover a repeated instruction according to the debugger’s stepping behaviour; use the stopped memory view as evidence of the final copy.

Range and overlap mistakes

If a JR target moves too far away as you add code, use a permitted JP form or rearrange the routine. Do not truncate the displacement. JR only supports unconditional, NZ, Z, NC and C conditions; DJNZ has its own relative form. Conditions such as PE and M require other branch forms.

Copy direction matters when source and destination overlap. Forward copying from a lower source into a higher overlapping destination can overwrite bytes before reading them. LDDR copies backwards when you initialise pointers to the last bytes. Neither direction makes an out-of-bounds copy safe. A count of zero passed to a repeating block instruction is not a request to skip it; guard it explicitly.

Exercise: change both the source data and count to six, reserve six destination bytes and verify all six results. Then deliberately leave the reservation at four and explain why a successful assembly would not prove the memory write is valid. Repair the bounds before running.

Z80 instruction reference

This reference covers the documented instruction mnemonics accepted by Studio’s Z80 source gate. It describes common forms, purpose, flag effects and mistakes worth checking. It is not an exhaustive opcode/clock table. The selected SjASMPlus validates operand combinations. r denotes a permitted eight-bit register, rr a permitted pair, n a byte, nn a word and d a signed indexed displacement; not every form permits every register.

Read conditions and flags precisely

NZ/Z test zero clear/set; NC/C test carry clear/set; PO/PE test P/V clear/set; P/M test sign clear/set. P/V may mean parity, overflow or a remaining block count depending on the producing instruction. CALL, JP and RET support all these conditions; JR supports only NZ,Z,NC,C. Undocumented flag bits, undocumented opcodes and CPU extensions are outside this reference.

ADC

Forms: ADC A,n; ADC A,r; ADC A,(HL); ADC HL,rr.

Add the operand and incoming carry. Eight-bit forms update S,Z,H,P/V,N,C, with N cleared; the HL form provides full 16-bit arithmetic flags. Use for the higher part of a multi-byte sum after adding its low part. Clear carry first if it is not an input.

ADD

Forms: ADD A,n; ADD A,r; ADD A,(HL); ADD HL,rr.

Add without using incoming carry. Eight-bit forms set arithmetic result flags and clear N. ADD HL,rr changes H,N,C while preserving S,Z,P/V; do not test Z afterwards to ask whether the 16-bit sum is zero. Index-pair additions have restricted pair operands.

AND

Forms: AND n; AND r; AND (HL).

Bitwise mask A, storing the result in A. Sets S,Z and parity; H is set, N and C are cleared. AND 7 extracts three low bits. It does not implement BASIC’s numeric conditional AND semantics.

BIT

Forms: BIT b,r; BIT b,(HL); BIT b,(IX+d).

Test a constant bit number 0–7 without changing the operand. Z is set when the bit is zero; P/V follows Z, H is set, N cleared and C preserved. S is significant for a test of bit 7. Branch on Z/NZ immediately.

CALL

Forms: CALL address; CALL condition,address.

Push the next instruction address and enter a subroutine, optionally for NZ,Z,NC,C,PO,PE,P or M. Flags are unchanged by CALL itself; the called routine may change them. Every taken call needs a compatible return and valid writable stack space.

CCF

Forms: CCF.

Complement carry; old carry is reflected in H and N is cleared. S,Z,P/V are preserved. Use only when the carry flag is the deliberate input. It does not complement A or convert a signed comparison into an unsigned comparison.

CP

Forms: CP n; CP r; CP (HL).

Set arithmetic flags for A minus the operand without changing A. Z means equal; C means A was smaller for an unsigned comparison. Signed comparison must consider overflow as well as the sign flag. The following arithmetic instruction may destroy this result.

CPD

Forms: CPD.

Compare A with (HL), decrement HL and BC. C is preserved; P/V indicates whether BC remains nonzero. The Z flag reports equality. Initialise BC and the pointer deliberately; this operation does not stop on a match by itself.

CPDR

Forms: CPDR.

Repeat CPD until equality or BC reaches zero. It searches backwards. Test Z to distinguish a match from count exhaustion, and remember HL has moved past the compared byte. An initial zero BC causes a very large search rather than no search.

CPI

Forms: CPI.

Compare A with (HL), then increment HL and decrement BC. C is preserved and P/V reflects the remaining count. It is useful for a manually controlled bounded search where you also need to perform work between bytes.

CPIR

Forms: CPIR.

Repeat CPI until equality or BC reaches zero. HL ends one byte beyond the last comparison. Test Z before assuming you found the value. Guard an empty range before entering; an initial BC of zero does not mean an empty search.

CPL

Forms: CPL.

Invert every bit of A. H and N are set; S,Z,P/V,C are preserved. For example $0F becomes $F0. Because Z is not recomputed, follow with an appropriate test if you need to branch on the new value.

DAA

Forms: DAA.

Adjust A after packed-BCD addition or subtraction using A and the previous H,N,C state. It affects S,Z,H,P/V,C and preserves N. It is not a binary-to-decimal conversion; do not insert unrelated flag-changing instructions before it.

DEC

Forms: DEC r; DEC (HL); DEC rr.

Subtract one. Eight-bit forms update S,Z,H,P/V,N but preserve C; P/V marks overflow at the signed boundary. Sixteen-bit pair forms preserve flags. DEC BC followed by JP NZ therefore does not test whether BC became zero.

DI

Forms: DI.

Disable maskable interrupts without changing arithmetic flags. It does not disable a non-maskable interrupt. A routine that leaves interrupts disabled can break keyboard handling, timing and HALT-based waiting. Preserve the calling environment rather than adding DI as a general crash remedy.

DJNZ

Forms: DJNZ label.

Decrement B and take a relative branch if B is nonzero, leaving flags unchanged. An initial B of zero yields 256 iterations. The target has the same signed displacement range as JR. It is useful for small, explicitly bounded loops.

EI

Forms: EI.

Enable maskable interrupts, with acceptance delayed until after the following instruction. Arithmetic flags are preserved. Do not issue EI merely to undo DI if the caller intentionally had interrupts disabled. The correct interrupt policy belongs to the machine and calling contract.

EX

Forms: EX DE,HL; EX AF,AF'; EX (SP),HL.

Exchange the stated values. The stack form swaps a pair with two bytes at SP and also has IX/IY forms. EX DE,HL changes no flags; exchanging AF exchanges the flags too. An invalid stack address makes the stack form unsafe.

EXX

Forms: EXX.

Exchange BC,DE,HL with their alternate banks. AF is unaffected. It is fast register-bank switching, but a BASIC caller or interrupt routine may rely on those alternate values. Do not treat the alternate bank as unowned spare memory.

HALT

Forms: HALT.

Suspend normal instruction progress until an interrupt condition releases the halt state. Arithmetic flags are unchanged. On an ordinary Spectrum Run session it can synchronise with interrupts; the standalone Debug snapshot does not promise a ROM interrupt environment. A disabled-interrupt HALT can appear permanently stuck.

IM

Forms: IM 0; IM 1; IM 2.

Select the maskable interrupt mode. Flags are unchanged. Mode 2 requires a valid vector arrangement and handler; selecting it alone installs neither. Stock Spectrum ROM operation normally relies on its established interrupt environment. This is advanced machine programming, not a beginner delay instruction.

IN

Forms: IN A,(n); IN r,(C).

Read an I/O port. The immediate form uses A for the upper address byte and leaves flags unchanged. The (C) form uses BC, updates S,Z,parity, clears H,N and preserves C. Ports are hardware-specific; the same number is not a RAM address.

INC

Forms: INC r; INC (HL); INC rr.

Add one. Eight-bit forms update S,Z,H,P/V,N and preserve carry; pair forms preserve flags. An eight-bit result wraps from 255 to zero. Use a deliberate wide counter when 256 distinct positions are insufficient.

IND

Forms: IND.

Read the port addressed by BC into (HL), decrement HL and B. The port and memory effects require a peripheral-specific contract. Block-I/O flags have special rules; do not interpret P/V as an ordinary arithmetic overflow result. Prefer explicit simple I/O while learning.

INDR

Forms: INDR.

Repeat IND until B reaches zero. A zero initial B produces 256 transfers. The high port-address byte changes as B changes, which matters on partially decoded hardware. Bound both the destination span and the device interaction.

INI

Forms: INI.

Read from the BC port into (HL), increment HL and decrement B. It is a block-I/O primitive rather than a general memory load. Its flag behaviour is specialised; use the device protocol and Z80 manual before relying on it.

INIR

Forms: INIR.

Repeat INI until B becomes zero. A count of zero means 256 transfers. Do not apply it to a keyboard port as though it were reading an independent sequence of characters. A matrix scan and a byte-stream peripheral have different contracts.

JP

Forms: JP label; JP condition,label; JP (HL).

Transfer control to a full address. Conditional forms support all eight standard conditions. JP (HL), (IX) or (IY) uses the pair’s value as the target; it does not fetch a pointer from memory there. Flags are preserved.

JR

Forms: JR label; JR condition,label.

Short relative jump, unconditional or using NZ,Z,NC,C only. The displacement is measured from the end of the instruction and must fit -128–127. Flags are preserved. Use JP for a distant target or an unsupported JR condition.

LD

Forms: LD r,n; LD r,r; LD r,(HL); LD rr,nn.

Move data using a permitted operand pair. Source storage normally remains unchanged. Most forms preserve flags; LD A,I and LD A,R update S,Z,H,N and use P/V for the interrupt-enable state. There is no general arbitrary memory-to-memory form.

LDD

Forms: LDD.

Copy (HL) to (DE), decrement both pointers and BC. S,Z,C are preserved; H,N are cleared and P/V indicates BC is nonzero. One invocation copies one byte, even if the incoming count was zero.

LDDR

Forms: LDDR.

Repeat LDD until BC is zero. Initialise pointers at the last bytes for backward copying. It handles a suitable overlapping range when copying from high addresses downwards. A zero initial count wraps into 65536 transfers; guard it first.

LDI

Forms: LDI.

Copy (HL) to (DE), increment both pointers and decrement BC. S,Z,C are preserved, H,N cleared and P/V reflects the remaining count. This supports a copy loop with extra work between transfers.

LDIR

Forms: LDIR.

Repeat LDI until BC becomes zero. It is a compact forward copy, not a bounds check. Initialise nonzero count, valid pointers and adequate destination capacity. The Z flag is preserved rather than indicating completion; BC is the completed counter.

NEG

Forms: NEG.

Replace A with zero minus A and set subtraction flags. Zero remains zero; $80 remains $80 and sets overflow because positive 128 is not an eight-bit signed value. Carry is set for a nonzero input. It is arithmetic negation, not bitwise inversion.

NOP

Forms: NOP.

Perform no data operation and preserve flags. PC advances and time is consumed. It is useful as a deliberate breakpoint location or small fixed delay component, but a pile of NOPs is not a portable long-duration timer.

OR

Forms: OR n; OR r; OR (HL).

Bitwise inclusive OR into A. S,Z and parity describe the result; H,N,C are cleared. OR A tests whether A is zero while leaving its bits unchanged. It also clears carry, which is useful before a 16-bit subtraction.

OTDR

Forms: OTDR.

Repeat OUTD until B is zero. It writes backwards through a buffer to a hardware port whose upper address byte changes with B. Initial B zero means 256 writes. Ordinary arithmetic interpretations of the specialised block-I/O flags are unsafe.

OTIR

Forms: OTIR.

Repeat OUTI until B is zero. It writes a forward buffer to the device. It is not a substitute for a protocol that requires readiness polling or stable full port addresses. Validate the device’s requirements before using a repeating transfer.

OUT

Forms: OUT (n),A; OUT (C),r.

Write to an I/O port, preserving arithmetic flags. The immediate form uses A as the high address byte; the (C) form uses BC. A port write can alter sound, border or memory mapping. Preserve unrelated hardware bits when the register combines functions.

OUTD

Forms: OUTD.

Write (HL) to the output port with B decremented as part of the operation, then move HL backwards. B is the transfer counter and participates in port addressing. Its flags are specialised, so use a documented peripheral sequence.

OUTI

Forms: OUTI.

Write a buffer byte to the output port, decrement B and increment HL. The block-I/O ordering and flags differ from ordinary OUT followed by a generic loop. It belongs in a device-specific routine with a clear count and pointer contract.

POP

Forms: POP BC; POP DE; POP HL; POP AF.

Read a pair from the stack and increase SP by two; IX/IY forms also exist. POP AF replaces the flags; other pairs do not. It must match your stack layout. Restoring pairs in the wrong order silently changes register values.

PUSH

Forms: PUSH BC; PUSH DE; PUSH HL; PUSH AF.

Decrease SP and save a register pair; IX/IY are also accepted pairs. Arithmetic flags are preserved. Account for two bytes per push plus return addresses, and pop in reverse order before a normal RET.

RES

Forms: RES b,r; RES b,(HL); RES b,(IX+d).

Clear bit 0–7 in the specified byte and preserve flags. For example RES 7,A removes the top bit. It does not report whether the bit was previously set; use BIT first if you need that information.

RET

Forms: RET; RET condition.

Pop a return address and resume the caller, optionally on a standard condition. Flags are unchanged by the return itself. A conditional return that is not taken falls through. A top-level Spectrum Run routine needs a balanced caller stack.

RETI

Forms: RETI.

Return from a maskable interrupt service routine and provide the daisy-chain peripheral return indication. It restores interrupt-enable state from the saved internal flip-flop. It is not a general substitute for RET in a BASIC-called routine.

RETN

Forms: RETN.

Return from a non-maskable interrupt routine, restoring the interrupt-enable flip-flop state. Arithmetic flags are unchanged. Use only with a correctly constructed interrupt entry/exit convention, rather than as a way to recover from an ordinary programme error.

RL

Forms: RL r; RL (HL); RL (IX+d).

Rotate a byte left through carry. Old carry enters bit zero; old bit seven becomes carry. S,Z and parity reflect the new byte; H,N are cleared. Useful for multi-byte shifts when carry deliberately connects neighbouring bytes.

RLA

Forms: RLA.

Rotate A left through carry. Unlike RL A, S,Z,P/V are preserved; H,N are cleared and C receives old bit seven. Choose the form based on the flags you need, not merely the resulting accumulator bits.

RLC

Forms: RLC r; RLC (HL).

Rotate left circularly: old bit seven enters bit zero and carry. S,Z and parity reflect the result; H,N clear. All eight bits are retained, unlike a shift that inserts zero.

RLCA

Forms: RLCA.

Rotate A left circularly, copying old bit seven to bit zero and carry. S,Z,P/V remain unchanged; H,N clear. It is not a zero test of the rotated value. Use RLC A if you need the general-form result flags.

RLD

Forms: RLD.

Rotate nibbles between the low half of A and both halves of (HL); A’s high nibble remains unchanged. S,Z and parity describe the new A; H,N clear and C is preserved. It can rearrange decimal digits but does not validate BCD data.

RR

Forms: RR r; RR (HL); RR (IX+d).

Rotate right through carry. Old carry enters bit seven and old bit zero becomes carry. S,Z and parity describe the result; H,N clear. Process the high byte first when shifting a multi-byte unsigned value right.

RRA

Forms: RRA.

Rotate A right through carry, preserving S,Z,P/V rather than recomputing them. H,N clear and C receives old bit zero. The shorter accumulator family and general register family have deliberately different flag behaviour.

RRC

Forms: RRC r; RRC (HL).

Rotate right circularly, copying old bit zero into bit seven and C. S,Z and parity describe the result; H,N clear. It wraps a bit pattern rather than performing unsigned division.

RRCA

Forms: RRCA.

Rotate A right circularly while preserving S,Z,P/V. H,N clear and C receives old bit zero. If you subsequently branch on Z, you are using an earlier zero result, not the newly rotated A.

RRD

Forms: RRD.

Rotate nibbles in the opposite direction to RLD between A’s low nibble and (HL). The high nibble of A is preserved. S,Z and parity reflect A, H,N clear and C is preserved. Keep the pointer within writable data.

RST

Forms: RST 0; RST 8; ...; RST 56.

Call one of eight fixed vectors at multiples of eight through $38. A return address is pushed and flags are unchanged by RST itself. Vector contents are machine-specific. RST $10 prints on a Spectrum only with the required ROM environment.

SBC

Forms: SBC A,n; SBC A,r; SBC HL,rr.

Subtract operand and incoming carry, using carry as borrow. Result flags include signed overflow and N is set. Clear carry before a standalone subtraction; propagate it deliberately from the low part for multi-byte subtraction.

SCF

Forms: SCF.

Set carry, clear H and N, and preserve S,Z,P/V. It prepares an explicit carry input. If you need carry clear, an instruction such as OR A can do that but also changes other flags; choose according to your contract.

SET

Forms: SET b,r; SET b,(HL); SET b,(IX+d).

Set bit 0–7 in a byte and preserve flags. SET 6,(HL) can enable brightness in an attribute byte. Check the destination and preserve other hardware meanings; a valid bit instruction can still write to the wrong address.

SLA

Forms: SLA r; SLA (HL).

Shift left, inserting zero at bit zero and moving old bit seven to carry. S,Z and parity reflect the result; H,N clear. This doubles an unsigned value modulo 256 and signals the discarded high bit.

SRA

Forms: SRA r; SRA (HL).

Shift right while retaining the sign bit; old bit zero goes to carry. S,Z and parity reflect the result; H,N clear. For negative odd values this rounds towards negative infinity, which differs from truncating signed division towards zero.

SRL

Forms: SRL r; SRL (HL).

Shift right with zero inserted at bit seven. Old bit zero becomes carry; S,Z and parity describe the result and H,N clear. It halves an unsigned byte and discards the fractional part.

SUB

Forms: SUB n; SUB r; SUB (HL).

Subtract from A without incoming borrow. Set S,Z,H,P/V,N,C, with N set. Carry indicates unsigned borrow; overflow indicates a signed result outside range. For a wider subtraction use SBC for higher bytes.

XOR

Forms: XOR n; XOR r; XOR (HL).

Bitwise exclusive OR into A. S,Z and parity reflect the result; H,N,C clear. XOR A produces zero and sets Z. XORing the same mask twice restores the original bits, useful for controlled toggles but not a replacement for saved state.

Accepted assembler directives

Directives guide assembly; they are not CPU instructions. They can emit data that a processor will misinterpret if execution falls into it. Put RET or an intentional branch before inline tables.

ORG

Form: ORG 24576.

Exactly one decimal origin is required for Spectrum; 16514 is the ZX81 origin. Put it before other directives/instructions. ORG $6000 is rejected by Studio despite being equivalent numerically.

EQU

Form: count: EQU 4.

Define a named constant, using Studio’s colon-label form. It emits no bytes and is not a valid source breakpoint. Keep its definition after ORG for this workflow.

DB

Form: DB 1,2,3.

Emit bytes or a quoted byte string. DEFB is an alias. Keep string content ordinary ASCII; semicolons begin comments in the preliminary scanner, even inside a string.

DEFB

Form: DEFB 65,66.

Alias of DB. Values must fit the assembler’s byte representation. A zero terminator is present only if you explicitly emit it.

DW

Form: DW $1234.

Emit little-endian words; DEFW is an alias. Addresses in a word table require word-aware pointer loading rather than a single-byte read.

DEFW

Form: DEFW message.

Alias of DW. The assembler resolves a label to its address. This is data, not an indirect jump.

DS

Form: DS 16,0.

Reserve a literal decimal byte count with an optional decimal fill byte 0–255. Aggregate DS/DEFS reservation is bounded at 16384 bytes, and the smaller Spectrum total code budget still applies.

DEFS

Form: DEFS 8,0.

Alias of DS. Expressions, negative counts and nondecimal counts are rejected by Studio’s gate. Reservation must fit the final 8192-byte image including instructions and other data.

What a successful build establishes

All names above pass the mnemonic gate, but wrong operands, an out-of-range branch, an unknown label or excess output can still fail. A successful build establishes assembly and packaging, not safe pointers, correct arithmetic, balanced stack use or observed runtime output. Includes, macros, scripts, multiple instructions on one line, undocumented SLL and Z80N forms remain unavailable. Keep experiments within the implemented single-source model.

Z80 arithmetic and comparisons

A register does not remember whether a number is signed. You decide that when interpreting the bit pattern and flags. The byte $FF is 255 unsigned or -1 signed. Adding one gives zero in both cases, but carry and signed overflow answer different questions. Keep your units and ranges beside each variable: a screen column, a score and a signed movement can all need different tests.

Carry is not signed overflow

ADD A,1 at A=255 produces zero and sets carry. At A=127 it produces $80, representing -128 signed, and sets overflow. The unsigned result 128 is perfectly valid in the latter case. CP sets subtraction flags without storing the subtraction. For unsigned A compared with a limit, C means smaller and Z means equal. NC means greater or equal. Signed less-than uses the relationship between S and overflow; testing M alone after CP fails near signed wrap boundaries.

Use explicit range checks where possible. For an unsigned column, test the lower and upper bounds before moving it. Do not let DEC wrap zero into 255 and assume a later screen routine will fix it. In a game, a clamped coordinate and a wrapped coordinate are different design choices.

Sixteen-bit addition and subtraction

    ORG 24576
    PUSH HL
    PUSH DE
    LD HL,1000
    LD DE,250
    ADD HL,DE
    LD (sum),HL
    OR A
    SBC HL,DE
    LD (difference),HL
    POP DE
    POP HL
    RET
sum:
    DW 0
difference:
    DW 0

Expected memory: sum is $04E2 (1250), stored E2 04; difference is $03E8 (1000), stored E8 03. OR A clears carry before SBC HL,DE. Without it, a carry inherited from earlier work would subtract an extra one. ADD HL,DE does not refresh Z, so this listing stores the result rather than making a false zero test.

For a value wider than a word, add the low bytes with ADD and the higher bytes with ADC. Subtract low bytes with SUB and higher bytes with SBC. Do not insert AND, OR or an unrelated comparison between stages: they change carry. Write a test case that crosses a byte boundary, such as 255+1, rather than testing only small numbers.

Logical masks and shifts

AND keeps bits selected by a mask; OR sets selected bits; XOR toggles them. To change the ink of a Spectrum attribute, preserve its upper five bits and replace the low three. AND 248 removes old ink, then OR the new value 0–7. Adding a colour value without clearing the old bits can spill into paper and brightness.

SLA shifts left and exports the high bit to carry; SRL shifts right and exports the low bit. SRA retains the sign bit for signed values. To shift a word left, shift its low byte first and rotate its high byte through carry. To shift right, begin with the high byte and pass carry into the low one. Circular rotation wraps the discarded bit back around and therefore is not ordinary multiplication or division.

Counts, wraparound and decimal digits

A B counter of zero before DJNZ means 256 iterations. BC=0 before LDIR means 65536 copies. Add an empty-range check when a count comes from data. DEC BC preserves flags, so test a 16-bit count by copying B to A and OR C, taking care that this overwrites A and changes carry.

Packed BCD stores two decimal digits per byte, each nibble 0–9. DAA adjusts a preceding BCD addition or subtraction according to its flags. It is not needed for a binary score displayed by a conversion routine, and it does not convert an arbitrary binary byte into two decimal digits. Decide on one representation and test rollover at 09 and 99 before using BCD in a larger programme.

A small verification matrix

For addition test zero, a normal pair, 255+1 and 127+1. For subtraction test equal values, a smaller minuend and a signed-boundary crossing. Record the result byte and C,Z,P/V flags while stopped. For pointer arithmetic also test the first and last valid address. An arithmetic result can be numerically correct and still be an invalid hardware address.

Z80 loops, tables and routines

A useful routine has a small contract: where its input arrives, how much data is valid, where its output appears and which registers it changes. Decide that before choosing instructions. A comment such as “HL points to count readable bytes; DE points to count writable bytes” is more valuable than a comment repeating “load HL”.

Counted loops

Use a literal positive count for the first version of a loop. DJNZ is convenient for 1–256 iterations when B is available. For a data-driven count, test zero before entry, and remember that using B for a loop also changes the high half of BC. A port routine using BC cannot simultaneously assume B remains an unrelated counter.

    ORG 24576
    PUSH HL
    PUSH BC
    LD HL,values
    LD B,4
    XOR A
again:
    ADD A,(HL)
    INC HL
    DJNZ again
    LD (total),A
    POP BC
    POP HL
    RET
values:
    DB 2,4,6,8
total:
    DB 0

Expected result: total becomes 20. The input table is four bytes, so B=4 exactly matches its length. INC HL and DJNZ leave the accumulator result intact. This byte accumulator intentionally supports only totals through 255; adding a fifth value without extending the table and count coherently is a bug. If the total can grow larger, use a wider accumulator and an explicit carry path.

Terminated strings and capacity

A zero-terminated string ends with a byte you explicitly place after its characters. A loop that searches only for zero is unbounded if the terminator is missing or the pointer is wrong. Pair the terminator with a maximum length, or use a length-prefixed table. Explain whether the terminator is part of the capacity and whether the destination needs its own terminator.

Word tables hold two bytes per entry. Doubling an index in an eight-bit register can overflow before you add it to the base pointer. Validate the index against the table size first, then use suitable-width arithmetic. A memory dump helps distinguish a pointer table from a character string: the same bytes cannot be interpreted interchangeably.

Subroutine ownership

CALL and RET are a pair; PUSH and POP are another pair. Keep them balanced along every branch, including an early error exit. If a subroutine promises an output in A and carry as an error flag, do not POP AF immediately before RET: that would discard both results. Save only the input state that the contract says must survive.

In Spectrum Run examples, preserve IY and avoid changing alternate register banks. The ROM’s interrupt and workspace conventions matter when returning to BASIC or making ROM calls. A routine that writes its own data buffer is easier to test in both Run and Debug than one that depends on the interpreter. Keep hardware access in a small routine so the arithmetic and bounds are independently understandable.

Data must not become execution

Place RET before tables and reserved buffers in a callable top-level example. A source label marks a location; it does not stop the CPU from executing whatever bytes follow. DS zero bytes can decode as instructions and hide a missing return for a while. A debugger breakpoint is valid only at an emitting instruction start, not at a label-only line or arbitrary table byte.

Debugging method and exercises

Start at the entry breakpoint. Confirm the pointer and count, step one iteration, and check that the pointer advances by the expected amount. Continue to the instruction after the loop and compare the output with a hand calculation. Add a four-byte table with a known total near 255 to expose overflow. Then replace it with a wide sum and test the carry path.

For recovery, Stop the debugger, repair source, Save and build again. Source edits are blocked during Debug and a changed build cannot reuse an old source map. Self-modifying code invalidates source debugging. These constraints make a small deterministic example a better teaching tool than a routine whose instructions rewrite themselves.
